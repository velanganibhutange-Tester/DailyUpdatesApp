# Daily Updates App - Beginner Project Documentation

This document explains what this project is, which technologies it uses, how the frontend and backend are organized, how the database works, and how to run and inspect the application locally.

## 1. Project Summary

Daily Updates App is a web application for tracking employee daily work updates.

Main workflows:

- Employees can register, log in, add daily updates, view their own updates, edit their own updates, and delete their own updates.
- Managers can log in, view team updates, view updates for a selected employee, view update details, and delete updates.
- Users, roles, and daily updates are stored in a SQL Server LocalDB database.

## 3. Frontend Explanation

This project does not use React, Angular, Vue, or a separate frontend app.

The frontend is built using server-rendered Razor pages:

- `Views/Home/Index.cshtml` - home page and today's updates.
- `Views/Update/*.cshtml` - employee update screens.
- `Views/Admin/*.cshtml` - manager dashboard and manager detail screens.
- `Areas/Identity/Pages/Account/*.cshtml` - login, register, logout, forgot password, and reset password pages.
- `Views/Shared/_Layout.cshtml` - common page layout, navigation bar, styles, and footer.

Static frontend files live in:

- `wwwroot/js` - custom JavaScript.
- `wwwroot/lib` - third-party browser libraries.

The browser receives HTML generated by ASP.NET Core. When a user submits a form, the request goes to a controller or Razor Page handler on the backend.

## 4. Backend Explanation

The backend is an ASP.NET Core MVC application.

Important files:

| File | Purpose |
| --- | --- |
| `Program.cs` | App startup, dependency injection, database setup, Identity setup, route mapping |
| `Controllers/HomeController.cs` | Loads home page data |
| `Controllers/UpdateController.cs` | Employee daily update actions |
| `Controllers/AdminController.cs` | Manager-only actions |
| `Models/ApplicationDbContext.cs` | EF Core database context |
| `Models/Employee.cs` | Application user model, extends ASP.NET Identity user |
| `Models/DailyUpdate.cs` | Daily update database model |
| `Services/EmailSender.cs` | Sends password reset email if SMTP is configured |
| `Services/PasswordResetOtpService.cs` | Generates and validates OTP codes for password reset |

Backend request flow example:

1. User opens `/Update/Add`.
2. `UpdateController.Add()` returns the Add Update page.
3. User submits the form.
4. `UpdateController.Add(...)` validates the input.
5. The controller saves the update using `ApplicationDbContext`.
6. Entity Framework Core inserts the record into SQL Server.
7. User is redirected to `/Update/MyUpdates`.

## 5. Database Explanation

The app uses SQL Server LocalDB for local development.

Connection string location:

```json
"ConnectionStrings":{
  "DefaultConnection": "Server=(localdb)\\MSSQLLocalDB;Database=DailyUpdatesDB;Trusted_Connection=True;"
}
```

Database details:

| Item | Value |
| --- | --- |
| SQL Server instance | `(localdb)\MSSQLLocalDB` |
| Database name | `DailyUpdatesDB` |
| Authentication | Windows Authentication |
| SQL username/password | Not required |

The app creates the database automatically on startup through:

```csharp
await context.Database.EnsureCreatedAsync();
```

Important: this project currently does not use EF Core migrations. There is no `Migrations` folder. For this project, run the app once to create the local database and tables.

Main database tables:

| Table | Purpose |
| --- | --- |
| `AspNetUsers` | Users/employees |
| `AspNetRoles` | Roles such as `Manager` and `Employee` |
| `AspNetUserRoles` | Links users to roles |
| `DailyUpdates` | Daily work update records |

## 6. Prerequisites

Install these tools:

1. .NET 9 SDK
2. SQL Server LocalDB
3. Visual Studio 2022, Visual Studio Code, or JetBrains Rider
4. SQL Server Management Studio or Azure Data Studio for viewing the database

Check .NET:

```powershell
dotnet --version
```

Expected result: a `9.x` version.

Check LocalDB:

```powershell
sqllocaldb info
```

If `MSSQLLocalDB` appears, LocalDB is available.

## 7. How To Run The Project

Open PowerShell in the project folder:

```powershell
cd D:\DailyUpdatesApp\DailyUpdatesApp
```

Restore packages:

```powershell
dotnet restore
```

Build the project:

```powershell
dotnet build
```

Run the project:

```powershell
dotnet run
```

The terminal will show URLs similar to:

```text
https://localhost:5001
http://localhost:5000
```

Open the shown URL in your browser.

## 11. How To View The Database

Using SQL Server Management Studio:

1. Open SQL Server Management Studio.
2. Server name:

```text
(localdb)\MSSQLLocalDB
```

3. Authentication:

```text
Windows Authentication
```

4. Click Connect.
5. Expand `Databases`.
6. Open `DailyUpdatesDB`.
7. Open `Tables`.

Useful SQL queries:

```sql
SELECT Id, Email, UserName, Name, Role, EmailConfirmed
FROM AspNetUsers
ORDER BY Email;
```

```sql
SELECT Id, Name
FROM AspNetRoles
ORDER BY Name;
```

```sql
SELECT
    u.Email,
    u.Name,
    r.Name AS IdentityRole
FROM AspNetUsers u
LEFT JOIN AspNetUserRoles ur ON ur.UserId = u.Id
LEFT JOIN AspNetRoles r ON r.Id = ur.RoleId
ORDER BY u.Email;
```

```sql
SELECT
    d.Id,
    d.Date,
    d.CreatedAt,
    u.Email AS EmployeeEmail,
    u.Name AS EmployeeName,
    d.Feature,
    d.TicketNumber,
    d.TicketDescription,
    d.Status,
    d.Blockers,
    d.EstimatedHours,
    d.EstimatedMinutes,
    d.EstimatedSeconds,
    d.HasETAChange,
    d.ETAChangeDescription
FROM DailyUpdates d
INNER JOIN AspNetUsers u ON u.Id = d.EmployeeId
ORDER BY d.CreatedAt DESC;
```

## 14. Common Pitfalls

- Do not run `dotnet ef database update` unless migrations are added later.
- If the database is missing, run the app once.
- If LocalDB connection fails, confirm `(localdb)\MSSQLLocalDB` exists.
- If the manager user is missing, confirm the app is running in Development environment.
- If you change a user's role directly in SQL, log out and log back in.
- Do not commit real SMTP passwords or production connection strings.
- Do not manually edit Identity tables unless you understand the role/user relationship.

## 15. Best Practices For Future Development

- Add EF Core migrations before using this in a shared or production environment.
- Move secrets to user secrets, environment variables, or a secure secret store.
- Replace the seeded test manager account before publishing.
- Add a proper admin screen for managing users and roles.
- Add server-side and client-side validation for any new forms.
- Keep controller actions small and move complex business logic into services.
- Add automated tests for important flows such as registration, role access, and update creation.
